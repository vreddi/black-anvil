# Tsup Package Generator

An [Nx](https://nx.dev) plugin generator that creates a new TypeScript package configured to use **[tsup](https://tsup.egoist.dev)** as its bundler.

## Overview

This generator scaffolds a complete package setup optimized for **tsup**, a fast TypeScript bundler built on esbuild. It generates:

- A modern `package.json` with dual-package (ESM/CommonJS) support
- A `tsup.config.ts` configuration file
- TypeScript configuration files
- Nx project configuration

## Why tsup?

**tsup** is an excellent choice for building TypeScript packages because it:

- ⚡ **Fast**: Built on esbuild for lightning-fast builds
- 🎯 **Zero config**: Works out of the box with sensible defaults
- 📦 **Dual format**: Easily generates both ESM and CommonJS outputs
- 🔧 **TypeScript-first**: Native TypeScript support with automatic type definitions
- 🎨 **Simple**: Minimal configuration required for most use cases

## Usage

```bash
nx generate @blackanvil/nx-package-plugin:tsup-package
```

Or with options:

```bash
nx generate @blackanvil/nx-package-plugin:tsup-package \
  --name=@example/my-package \
  --description="My awesome package" \
  --platform=node-only
```

## Generated Package Structure

The generator creates a package with the following structure:

```
packages/
└── your-package/
    ├── src/
    │   └── index.ts
    ├── tsup.config.ts
    ├── tsconfig.json
    ├── package.json
    └── README.md
```

## Package.json Design

The generated `package.json` follows modern Node.js best practices, specifically designed to work seamlessly with tsup's output:

### Conditional Exports

The `exports` field is the recommended way to define package entry points in modern Node.js. Unlike the legacy `main` and `module` fields, `exports` provides:

- **Conditional resolution**: Different entry points can be resolved based on how the package is imported (`import` vs `require`)
- **Better encapsulation**: Only explicitly exported paths are accessible, preventing access to internal files
- **Future-proof**: Aligns with Node.js's direction for package entry points
- **tsup compatibility**: Works perfectly with tsup's dual-format output (ESM and CJS)

### Type-Aware Conditional Exports

In the conditional exports configuration, the `types` condition is placed first within each export condition because:

- **TypeScript and other type checkers** prioritize the `types` condition when resolving module types
- **Type-first resolution** ensures that TypeScript can find type definitions before resolving the runtime code
- **Better IDE support** provides accurate autocomplete and type checking during development

The structure allows TypeScript to resolve:

- `./dist/index.d.ts` for ESM imports (generated by tsup with `dts: true`)
- `./dist/index.d.cts` for CommonJS requires

### Files Field

The `files` field explicitly declares which files should be included when publishing to npm:

- **Security**: Prevents accidentally publishing sensitive files (e.g., `.env`, source code, test files)
- **Size optimization**: Only includes necessary files (typically `dist/`, `README.md`, `LICENSE`)
- **Predictability**: Makes it clear what consumers will receive when they install your package

This ensures that only the compiled output (`dist/`) generated by tsup and essential documentation files are published, keeping package size small and secure.

## Tsup Configuration

The generator creates a `tsup.config.ts` file with sensible defaults:

- **Dual format output**: Generates both ESM and CommonJS builds
- **Type definitions**: Automatically generates `.d.ts` files
- **Source maps**: Includes source maps for better debugging
- **Tree shaking**: Enabled for optimal bundle size
- **Clean builds**: Automatically cleans the output directory before building

You can customize the tsup configuration by editing `tsup.config.ts` in your generated package.

## Platform Options

The generator supports three platform options:

- **`node-only`**: For packages that run in Node.js (CLIs, Nx executors/generators, server utilities)
- **`browser-only`**: For packages meant to run in the browser (React components, UI utilities)
- **`node-and-browser`**: For universal packages that work in both environments

The platform selection affects the generated tsup configuration and package.json exports.

## Building Your Package

After generation, build your package with:

```bash
nx build your-package-name
```

Or run tsup directly:

```bash
nx run your-package-name:build
```
